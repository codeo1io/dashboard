## B2 — rm-262: cap the /auth/logout body

- **Change.** `src/routes/auth.ts`: POST /auth/logout now (1) prechecks
  `content-length` against `MAX_LOGOUT_BODY_BYTES = 16384` → 413, (2) reads
  the raw body and re-checks length → 413, (3) accepts ONLY
  `application/x-www-form-urlencoded` → 415 otherwise, (4) parses
  `csrf_token` via `URLSearchParams`. Mirrors the listener ingest cap
  (`MAX_INGEST_BODY_BYTES` / readBodyCapped).
- **Encoding narrowing is safe.** The only real caller
  (`web/src/shell/AppShell.tsx`) posts urlencoded `csrf_token`; every existing
  auth test posts urlencoded. `formData()`'s multipart acceptance was unused by
  any caller or test — the 415 keeps that honest instead of silently
  narrowing.
- **Tests.** auth.test.ts: oversized body (17KB) → 413; multipart content-type
  → 415.
- **Repo-wide guard — declined with rationale (recorded decision).** The
  acceptance asked for a guard that no OTHER public route parses an uncapped
  body. Grep shows `c.req.formData()` had exactly one site in src/ (this one,
  now gone) and `c.req.json()`-style raw parses on public paths have the
  listener's contract-tested cap. A lint rule would pin a single instance;
  recorded here as an invariant instead ("any new public body parse ships
  behind a cap") — future assess rounds check it by grep.
