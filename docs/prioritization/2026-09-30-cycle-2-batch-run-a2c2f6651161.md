## B3 — `rm-283` release-pipeline App-token blast-radius decision (priority 18)

Decision-shaped, recorded while cheap: both `release.yaml` App-token mints
are INERT on this fork — `gh api /repos/codeo1io/dashboard/actions/secrets`
reported `total_count` 0 (names empty), re-probed live 2026-10-01 during this
batch. The publication mint (`:381-385`, `APPLICATION_ID`/
`APPLICATION_PRIVATE_KEY`) is gated on `HAS_RELEASE_APP` (secret presence,
`:136`) and degrades to a warning + `ci-<run>` image tag without it; the
infra-dispatch mint (`:584-591`, `INFRA_DISPATCH_APP_ID`/
`INFRA_DISPATCH_APP_PRIVATE_KEY`) is the only place those secrets are read.

DECISION (per research R3 + upstream `fro-bot/dashboard` issue #112's
competing approach): **dedicated minimal-scope GitHub App per mint site**, not
a shared App with mint-time scoping. Rationale: mint-time scoping
(`repositories`, `permission-*` inputs to `actions/create-github-app-token`)
bounds the minted TOKEN, not the KEY — a holder of the private key + app id
can always mint a token with the App's FULL installed scope, so only the
App's own installation footprint bounds a key leak. Floors, binding on the
first provisioned secret:

- Publication App — installed on `codeo1io/dashboard` ONLY, with
  `contents:write` as its only permission. The token's entire job surface is
  in this one repo: create the CalVer tag ref (`POST /repos/.../git/refs`),
  `gh release create/view/edit`, and the failure-path cleanup
  (`DELETE /repos/.../git/refs/tags/<tag>` + release deletion). No other
  permission is needed — no actions, no checks, no members, no secrets read.
- Infra-dispatch App — installed on `marcusrbrown/infra` ONLY, with
  `actions:write` as its only permission, matching the mint-time constraints
  already written in the workflow (`owner: marcusrbrown`,
  `repositories: infra`, `permission-actions: write`). The token's only job
  is `gh workflow run deploy-dashboard.yaml` there.

Interim compensating controls (documented acceptance until provisioned):
zero secrets exist, both mints are presence-gated, and the release pipeline
explicitly degrades (warning + GHCR `ci-<run>` tag + no `:latest` CalVer
promotion) rather than failing. The AGENTS.md landing-pipeline section now
carries this decision so the first provisioned secret inherits it; workflow
text itself is out of this batch's file set (claimed by sibling lineages).
