## The change

`src/server.ts` — two named cache-policy middlewares defined before the SPA
shell block, applied at every static mount:

1. `hashedAssetImmutablePolicy` on `/assets/*` — after `next()`, sets
   `Cache-Control: public, max-age=31536000, immutable` on **200s only** (a 404
   for a dead hash must never be immutable). No ETag added: vite's
   `[name]-[hash]` output config (web/vite.config.ts:75-79, entry/chunk/asset)
   makes the URL itself the validator — a conditional request can never hit a
   changed representation. Deploy rollover stays immediate because the shell
   referencing the hashes is no-store (injected, rm-166) / no-cache (variant).
2. `unversionedCachePolicy` on `/icon-*`, `/manifest.webmanifest`, `/privacy`,
   `/privacy/`, the uninjected shell variant (`pushNotificationsEnabled` false),
   and the flag-gated `/static/*` catch-all — after `next()`, sets
   `Cache-Control: no-cache` **only when the header is absent**, so a
   co-registered policy (rm-478's ETag-bearing no-cache on
   `/static/operator-*.js`) always wins; those three mounts short-circuit the
   chain before the catch-all, so they are structurally untouched.

### Recorded policy decision (the "which policy" clause of the acceptance)

Uniform **`no-cache`** for every unversioned surface. Rationale:
(a) repo precedent — `/sw.js`/`/registerSW.js` already use
`no-cache, no-store, must-revalidate` (SW-update detection) and rm-478 uses
`no-cache` + content-hash ETag for the hot operator-runtime files;
(b) serveStatic adds no validators on these mounts, so `no-cache` degenerates
to refetch-every-time — byte-identical wire behavior to today's policy-null
responses, but explicit and immune to RFC 9111 §4.2.2 heuristic caching (which
may otherwise store a 200 without explicit freshness);
(c) correctness-first: these surfaces are tiny (manifest ~1 KB, icons ~KB,
privacy ~2 KB) while the ~285 KB hashed payload carries the perf win;
(d) `/sw.js` + `/registerSW.js` keep their pre-existing **stricter** policy —
satisfying the acceptance's "explicit short-revalidation, never immutable"
without downgrading SW update detection. A short `max-age` was rejected: it
would serve a stale shell/manifest (referencing dead `/assets` hashes) inside
the window after a deploy.
