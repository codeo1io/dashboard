## Hard-won API facts (probed live 2026-10-03, encoded in template comments/tests)

1. `vulnerabilityAlerts` exposes **no orderBy**, **ignores `last`**, and **caps
   pages at 10 nodes** (requesting `first: 20` still returns 10) — hence the
   cursor-walk design instead of a `last: N` recent slice.
2. `DependabotUpdate` has **no `state` field** — cure-PR reachability is
   `dependabotUpdate.pullRequest{state,url}`.
3. `EPSS.percentage/percentile` are String-typed but **serialized as bare JSON
   numbers**.
4. `firstPatchedVersion` is an object (`identifier`), not a scalar.
5. The REST surface supports `direction=desc` but the GraphQL surface (the
   app's read-only token discipline) does not — the walk stays on GraphQL.

## Lessons (durable)

1. **Client-bundle outbound URL literals trip the privacy guard.** Any URL the
   SPA must link out to is derived SERVER-side and shipped on the wire
   (`updatePrUrl` precedent, now `advisoryUrlFor`); never baked as a client
   literal. Detection recipe + full write-up:
   `docs/solutions/workflow-issues/client-bundle-outbound-url-literals-trip-privacy-guard-2026-10-03.md`.
   Process half: a batch adding a web view must run the privacy suite (and a
   bundle-origin grep) in targeted validation — the impacted-test selector does
   not pull in suites the implement did not touch.
2. **Targeted selector + package.json = full-CI fallback (push/pr/ci).** Record
   the selector decision with `--print-only`, rerun over the surfaces minus
   package.json with a no-op fallback, and cover package.json's blast radius
   with check-types + lint + actionlint.
3. **Pre-broken environment suites**: prove pre-existence with a stash
   round-trip before treating red as a regression (Node-26 jsdom localStorage:
   the App/AppShell/listener/push-vapid suite class).
